# CLI and Cross-cutting Design

## 1. CLI architecture

The unified CLI entrypoint is `lawgraph` (registered in `pyproject.toml`) and `python -m lawgraph`.

```
lawgraph <phase> <source> [options]
```

### Dispatch mechanism

`src/lawgraph/__main__.py` builds a `phase → source → main()` dispatch table from the source registry (`sources/registry.py`). Each `SourceDescriptor` in the registry declares retrieve, normalize, and semantic `main(argv)` functions.

Pipeline CLI functions are generated by `pipelines/factory.py::make_pipeline_cli(pipeline_cls, ...)`. This handles argument parsing, `ArangoStore` construction, `run()` invocation, error logging, and `sys.exit(1)` on failure.

| Phase | Sources |

### Special commands

| Command | Description |
|---------|-------------|
| `lawgraph bootstrap` | Bootstrap database collections, indexes, and analyzers |
| `lawgraph expand-graph` | Iterative fill-gaps loop |
| `lawgraph fill-gaps` | Diagnose and fill knowledge gaps |

## 2. Common CLI flags

### Retrieve

| Flag | Description |
|------|-------------|
| `--mode full\|incremental` | Full load or incremental update |
| `--since-days N` | Look back N days (default: source-specific) |

### Normalize and semantic

| Flag | Description |
|------|-------------|
| `--since DATE` | ISO 8601 date or relative (e.g. `7d`) |
| `--since-days N` | Look back N days; 0 = full history |

### TK dossiers retrieve (additional)

| Flag | Description |
|------|-------------|
| `--skip-personen` | Skip slow Persoon full-refresh |
| `--skip-stemmingen` | Skip Stemming fetch |
| `--stemmingen-since DATE` | Override `--since` for stemmingen only |
| `--skip-documents` | Skip Document fetch |
| `--documents-since DATE` | Override `--since` for documents (e.g. `730d`) |

### BWB semantic (additional)

| Flag | Description |
|------|-------------|
| `--store-citations` | Store detected hits as `props.citations` on source nodes |

### Version causes semantic (additional)

| Flag | Description |
|------|-------------|
| `--window-days N` | Look-back window in days (default: 365) |

## 3. Operational runbook

### Full initial load

```bash
# Retrieve all sources (full mode)
lawgraph retrieve all --mode full

# For TK dossiers, documents corpus is large — use a date window:
lawgraph retrieve tk-dossiers --documents-since 730d

# Normalize all
lawgraph normalize all

# Run semantic detection
lawgraph semantic all
```

### Incremental update (daily/weekly)

```bash
# Retrieve recent changes
lawgraph retrieve all --mode incremental --since-days 7

# TK dossiers incremental
lawgraph retrieve tk-dossiers --since 7d --skip-personen --stemmingen-since 7d --documents-since 7d

# Normalize only recent records
lawgraph normalize all --since 7d

# Re-run semantic detection
lawgraph semantic all
```

### Slow operations

| Command | Typical duration | Notes |
|---------|-----------------|-------|
| `retrieve tk-dossiers` (full) | ~15 min | 97K activiteiten + 116K documents |
| `normalize tk-dossiers` | ~30 min | 116K documents + 350K+ edges |
| `retrieve tk-content` | Hours | Rate-limited at 0.5 s/request; ~400K publications |
| `semantic bwb` | 5–10 min | Full scan of all instrument_articles |

### Skipping individual steps

All orchestrators respect skip env vars:

```bash
LAWGRAPH_RETRIEVE_SKIP_TK=1
LAWGRAPH_RETRIEVE_SKIP_TK_DOSSIERS=1
LAWGRAPH_NORMALIZE_SKIP_BWB=1
LAWGRAPH_SEMANTIC_SKIP_RECHTSPRAAK=1
LAWGRAPH_SEMANTIC_SKIP_JUDGMENT_CITATIONS=1
# etc.
```

## 4. Observability

### Logging

- **Module**: `lawgraph.core.logging` — `get_logger(__name__)`
- **Format**: `%(asctime)s [%(levelname)s] %(name)s: %(message)s`
- **JSON mode**: set `LAWGRAPH_LOG_FORMAT=json` for one-JSON-object-per-line output
- **Level**: controlled by `PIPELINE_LOG_LEVEL` env var (default: `INFO`)

### Pipeline result

Every `pipeline.run()` call returns a `PipelineResult` with `created`, `updated`, `skipped`, and `errors` counts. The factory-generated CLI logs a summary and lists all error messages.

### API request logging

Every HTTP request is logged with: `[request_id] client METHOD path status size latency_ms`.

### Health check

`GET /api/health` checks ArangoDB connectivity and returns `{"status": "ok", "database": "connected"}` or 503.

## 5. Security and configuration

### Authentication

There is no authentication on the API. All read endpoints and the watches write endpoint are publicly accessible.

### CORS

Configured via `LAWGRAPH_ALLOWED_ORIGINS` (comma-separated). Default: localhost:5173 and localhost:5174.

### Input validation

FastAPI `Path(pattern=...)` constraints are applied to route path params:

| Parameter | Pattern |
|-----------|---------|
| `bwb_id` | `^BWB[RrVv]\d{7}$` |
| `ecli` | `^ECLI:[A-Z]{2}:[A-Z0-9]+:\d{4}:[A-Z0-9._-]+$` |
| `kamerstuknummer` | `^\d+(-[A-Z]+)?$` |

Invalid formats return HTTP 422 automatically.

### Startup validation

The `lifespan` context manager warns on missing `ARANGO_URL`, `ARANGO_PASSWORD`, and `LAWGRAPH_ALLOWED_ORIGINS`.
